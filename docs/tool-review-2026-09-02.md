# Tool review: September 2, 2026

This review covers the tools declared in `Brewfile`, `Brewfile.apps`,
`.tool-versions`, the Linux package lists, and the installer, plus Cursor
because the repository manages its settings. It uses the repository contents
read during this conversation and current primary documentation and Homebrew
metadata. It is a recommendation, not an inventory of what is installed or used
on a particular machine. A fresh shell-based inspection failed before returning
output, so no installed versions or migration behavior were tested.

Here, a state-of-the-art default means a supported tool that fits the workflow,
integrates well, and earns its installation and maintenance cost. These are
editorial recommendations; no comparative performance benchmarks were run. An
old implementation language or infrequent release cadence alone is not a reason
to replace a tool.

**Keep** means retain the tool. **Optional** means install for a specific
project or personal workflow. **Remove** means remove the explicit manifest
entry, not force-uninstall a dependency or remove an operating-system component.

## Implementation follow-up

The shared Brewfiles and runtime pins now implement these recommendations. See
[package profiles](package-profiles.md) for the current installation policy. The
review below records the original findings. Repository validation and
live-machine package installation are separate; these edits do not uninstall
existing software.

## First changes I recommend

1. Rename the Homebrew Rust package to `rustup` and wire its actual executable
   directory. The current formula is keg-only and no longer provides
   `rustup-init`. Preserve project Rust toolchains.
   [Homebrew](https://formulae.brew.sh/formula/rustup)
2. Remove MakeMKV from the portable application bundle. Homebrew marks the cask
   deprecated for failing its Gatekeeper check and lists September 1, 2026 as
   its disable date. The fetched API snapshot was generated August 27 and still
   reported `disabled: false`; an actual install failure was not reproduced.
   This is a packaging finding, not proof the application is abandoned.
   [Cask metadata](https://formulae.brew.sh/api/cask/makemkv.json)
3. Remove `direnv`, `mas`, and the extra `dash` shell from the default Brewfile.
   They have no active public-repo integration. Use mise for directory
   environments; retain direnv only where a project's `.envrc` requires it. Mise
   discourages combining the two environment hooks.
   [Mise guidance](https://mise.jdx.dev/direnv.html)
4. Remove `tree` on macOS and explicit Linux `vim` entries. Use `eza --tree`
   where eza is installed and Neovim for terminal editing. Linux does not yet
   install eza, so preserve its `tree` until that gap is addressed.
   [Eza options](https://eza.rocks/#command-line-options)
5. Choose Ghostty as the minimal terminal default and keep Warp optional. This
   changes my earlier suggestion, which optimized for fewer configuration edits.
   Warp is current and its client became open source in April 2026; retain it if
   its integrated agent workspace is useful.
   [Ghostty](https://ghostty.org/docs/install/release-notes/1-3-0),
   [Warp announcement](https://www.warp.dev/blog/warp-is-now-open-source)
6. Choose VS Code plus Neovim as the default editor pair; remove Sublime and
   install Zed or Cursor when a specific workflow warrants them. The
   repository's C# and devcontainer settings make VS Code a practical default.
   [C# support](https://code.visualstudio.com/docs/csharp/get-started),
   [containers](https://code.visualstudio.com/docs/containers/overview)
7. Update runtime defaults to Node 24 LTS, Python 3.14 where dependencies
   support it, and .NET 10 LTS. Preserve older versions required by individual
   projects. Ruby needs a patch update now and a project-specific decision about
   3.4 or 4.0.
8. Move cloud tools, Swift tooling, media processing, and local models out of
   the unconditional base install. Keep them available as documented optional
   groups.
